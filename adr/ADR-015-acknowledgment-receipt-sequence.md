# ADR-015: Acknowledgment Receipt Numbering & Tracking

**Status:** Accepted  
**Date:** 2026-07-23  
**Deciders:** Architecture Team, Cashier Lead  

**References:**
- [ADR-006: Document-Centric Architecture](./ADR-006-document-centric.md) — the Acknowledgment Receipt is a business document with its own lifecycle (Draft → Issued → Voided/Closed)
- [ADR-019: AP Numbering Convention](./ADR-019-ap-numbering-convention.md) — AP uses A#### format (contrast with AR's YYYY-SEQ)
- This ADR defines the numbering and tracking mechanism for AR documents.

---

## Context

The company does not issue Official Receipts (OR). Instead, **Acknowledgment Receipts (AR)** serve as the primary receipt document for all collections.

### Key findings:

1. **Pre-numbered series:** ARs are pre-numbered (e.g., `2026-921`, `2026-922`, `52733`, `52810`)
2. **Different numbering patterns observed:**
   - `2026-921` → Year + sequential (for the monitoring sheet AR# column)
   - `52733`, `52810` → Sequential from a different series (for per-client payment references)
   - `309021`, `309033` → Another sequential series
3. **Tracking is manual:** "Monthly, per week, unorganized" (from shadow notes)
4. **One AR per transaction:** Each collection event receives one AR
5. **AR links to proof of payment:** The AR# is written on the POP and attached per cycle

### From the monitoring sheet:
```
TR No: 632, AR No: 2026-921, Amount: 2,850
TR No: 633, AR No: 2026-922, Amount: 1,300
```

### From the collection macro:
```
Disclosure column:
  "AR 52733 12/19/2025 = 51,500.00"
  "AR 52810 12/26/2025 = 51,600.00"
  "AR 53041 1/08/2026 = 76,175.00"
```

---

## Decision

**Model AR numbers as a system-managed sequential series with configurable prefix and year-based reset.**

### Rules

1. **Single AR number source:**
   - The system auto-assigns the next AR number when Mich creates a new collection
   - No manual entry of AR numbers — prevents duplicates and gaps

2. **Numbering format:**
   - Default: `YYYY-SEQ` (e.g., `2026-1001`), where SEQ resets annually
   - Configurable prefix to support different series if needed
   - The system tracks: first number, last number, and all numbers used

3. **Gap tracking:**
   - If an AR is voided, it is marked as "Voided" (not deleted)
   - Voided ARs are reported in a periodic audit log
   - Reports show: Total printed, Total used, Total voided, Available

4. **Integration with POP:**
   - AR# is automatically printed on the Acknowledgment Receipt form
   - POP can be attached/scanned against the AR# in the system
   - Per-cycle POP attachment is generated by the system (no manual printing)

5. **Multiple series support:**
   - Different AR series can exist per segment if needed
   - The monitoring sheet series (YYYY-SEQ) is separate from the macro's per-client series

---

## Consequences

### Positive
- Eliminates "unorganized" AR tracking
- Auto-assigned numbers prevent duplicates and skipped numbers
- Void tracking provides audit trail
- AR# is linked to the transaction at creation time (not entered later)

### Negative
- Existing pre-printed AR stock must be reconciled with system numbers
- Two numbering patterns observed in existing data — migration requires mapping
- Physical AR forms must match system-assigned numbers (or system replaces physical forms)

### Neutral
- The physical Acknowledgment Receipt form (ACCTG-FOR-005 v3) can remain the same template
- System-generated AR# replaces manual stamping/writing

## Data Model

```python
class ARSequence:
    id: int
    prefix: str              # "2026-", "2025-", etc.
    year: int                # Reset year
    next_number: int         # Next available number
    last_number: int         # Last assigned number

class AcknowledgmentReceipt:
    ar_number: str           # Full AR# (e.g., "2026-1001")
    transaction_id: str      # Links to the collection transaction
    amount: Decimal
    customer_id: str
    date_issued: date
    created_by: str          # Mich
    status: str              # "Issued", "Voided", "Cancelled"
    void_reason: str         # If voided
```
