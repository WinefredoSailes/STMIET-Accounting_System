# ADR-041 — Static Asset Cache Policy (WhiteNoise, No Hashed Filenames)

| Field | Content |
|-------|---------|
| **Status** | Accepted |
| **Date** | 2026-09-11 |
| **Decision** | Keep serving static assets (JS/CSS) via **WhiteNoise `CompressedStaticFilesStorage` with stable filenames** — no content-hash versioning (`ManifestStaticFilesStorage`). Browser-cached stale JS is handled by hard-refresh in local dev; on Render it self-heals per deploy. Revisit only if production users report stale-UI symptoms (trigger defined below). |
| **Context** | • On 2026-09-11 the Check Voucher form showed **Net −₱119.00** for Gross ₱1,212.42 / WHT ₱120.00.<br>• Root cause was **stale cached JS, not a logic bug**: the browser ran the old `gross-net-calc.js` (`parseFloat("1,212.42")` stops at the comma → `1`), while the page served the new comma-formatting inputs (`1 − 120 = −119`).<br>• Server-side posting was always correct: `money()` strips commas, so the saved JE net was ₱1,092.42. Display-only symptom.<br>• Local `runserver` serves working-tree statics with no cache-busting, so a cached script can linger across editing sessions indefinitely until hard-refresh (`Ctrl+Shift+R`).<br>• On Render each deploy builds a fresh Docker image and `collectstatic` re-runs in `dockerCommand` (ADR-040); WhiteNoise short cache lifetimes mean any staleness self-heals within ~a minute. Residual window: a user mid-session at the exact deploy moment. |
| **Decision Drivers** | 1. **Incident cost was confusion, not data corruption** — postings were correct; only the live net preview mis-rendered.<br>2. **Production self-heals** — fresh image per deploy + short WhiteNoise cache lifetimes; no persistent stale window on Render.<br>3. **Zero change, zero deploy discipline** — hashed-filenames require no code change but add a failure mode if `collectstatic`/manifest ever misbehaves; current setup already works (ADR-040 driver 7).<br>4. **Scale** — 3–6 users; a ~60s post-deploy staleness window for mid-session users is acceptable. |
| **Consequences** | **Positive**<br>• No code or settings change; no new deploy step.<br>• Local dev rule is simple: after pulling JS changes, hard-refresh once (`Ctrl+Shift+R`).<br>• Display-vs-posting split stays explicit: live previews are convenience; `money()` + `PostingService` are the source of truth (ADR-002).<br><br>**Trade-offs**<br>• A mid-deploy production session can show stale JS for ~a minute; user remedy is a normal refresh.<br>• Future JS refactors that change input formatting (e.g. `type=number` → comma-formatted `type=text`) must update the consuming calc in the same commit, or the old-script/new-markup mismatch recurs (exactly this incident's shape). |
| **Revisit Trigger** | If a **production (Render) user** reports stale-UI behavior (old formatting, frozen calc, mismatched preview) that a refresh fixes, adopt **`whitenoise.storage.CompressedManifestStaticFilesStorage`** (content-hashed filenames + long cache headers): new deploy = new URL = browsers fetch fresh assets exactly once, then re-cache. `collectstatic` already runs in `dockerCommand`, so the change is settings-only. |
| **Co-related ADRs** | ADR-040 (Render deploy) → fresh image + `collectstatic` per deploy; short WhiteNoise cache lifetimes.<br>ADR-036 (UI frontend) → HTMX/Tailwind + page-level JS (`line-grid.js`, `gross-net-calc.js`, `amount-format.js`).<br>ADR-002 (no force-balance) → server-side totals are authoritative; JS previews never post. |
| **Status** | Accepted |

---

*Reference for any future stale-asset incident: check browser cache age of the page's JS first (`Ctrl+Shift+R`), then compare the served script against the committed version before assuming a logic bug.*
